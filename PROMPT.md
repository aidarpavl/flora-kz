# СУПЕР-ПРОМТ v2 — «Флора Казахстана»: полный клон страницы проекта iNaturalist на Streamlit + Supabase

> Этот промт самодостаточен: по нему LLM или разработчик может с нуля воспроизвести проект.

## 1. Роль
Ты — senior full-stack разработчик (Python, Streamlit, PostgreSQL/PostGIS, Supabase) и GIS-специалист.
Пишешь production-код с комментариями на русском; интерфейс полностью на русском языке.

## 2. Цель
Сделать веб-приложение **«Флора Казахстана»**, которое **повторяет страницу проекта iNaturalist**
https://www.inaturalist.org/projects/flora-kazahstana (все вкладки, счётчики, карточки, карты),
но работает **на собственной базе Supabase** и добавляет **разрез по территориям**:
**Весь Казахстан → Области (ADM1) → Природные зоны** (лесостепь, степь, полупустыня, пустыня,
Алтай, Саур-Тарбагатай, Джунгарский Алатау, Северный Тянь-Шань, Каратау).

## 3. Эталон: что есть на странице проекта iNaturalist (повторить)
1. **Шапка**: баннер проекта (зелёный фон `#74AC00`, название «Флора Казахстана», описание проекта, ссылка на iNaturalist).
2. **Строка счётчиков-вкладок**: `Обзор` · `N НАБЛЮДЕНИЙ` · `N ВИДОВ` · `N ЭКСПЕРТОВ` (определителей) · `N НАБЛЮДАТЕЛЕЙ` · кнопка `Статистика`.
3. **Обзор**:
   - «Последние наблюдения» — карусель/сетка карточек: фото, название (рус./лат., ранг для родов и семейств), число определений, давность («2 мес»), аватар/логин автора;
   - три колонки-лидерборда: **Больше всего наблюдений** (топ-6 наблюдателей), **Больше всего видов** (топ-6), **Чаще всего наблюдают** (топ-6 видов с миниатюрой); у каждого кнопка «Посмотреть все»;
   - **Требования проекта** (место: Казахстан; качество: исследовательский уровень + требуется идентификация);
   - **Статистика** — кольцевая диаграмма уровней качества (Исследовательский / Требуется идентификация / Обыкновенное);
   - **Карта наблюдений** — все точки проекта (сеткой-теплокартой при отдалении, точками при приближении).
4. **Наблюдения**: переключатель вида **Карта / Сетка / Таблица**; фильтры (вид, качество, наблюдатель, даты, территория); пагинация; клик → карточка наблюдения со ссылкой на iNaturalist.
5. **Виды**: сетка карточек (фото, бейдж «N наблюдений», общее название, латинское курсивом), сортировка по числу наблюдений, поиск, «Показать ещё».
6. **Эксперты (определители)**: таблица — место, логин (ссылка на профиль), число определений чужих наблюдений.
7. **Наблюдатели**: таблица — место, логин, наблюдений, видов; сортировка по любому столбцу.
8. **Статистика**: наблюдения по годам и месяцам (сезонность), уровни качества, топ семейств и родов, рост числа видов во времени.
9. **Страница вида** (как taxon page): галерея фото из наблюдений, рус./лат./англ. названия, семейство/род, карта находок, сезонность по месяцам, области и зоны, где встречается, ссылки на iNaturalist и Википедию.

## 4. Дополнительно к iNaturalist (наша специфика)
- **Глобальный фильтр территории в боковой панели** (Весь Казахстан / область / природная зона) — применяется ко ВСЕМ вкладкам и счётчикам.
- **Вкладка «Карта территорий»**: хороплет областей или природных зон по числу видов, клик по полигону выбирает территорию; таблица рейтинга территорий.
- Все точки координат берутся **из базы данных**, не из API iNaturalist.

## 5. Данные и архитектура
### 5.1 Загрузка (ETL) — внутри Supabase, без внешних ключей
- Расширения: `http` (запросы к API), `postgis` (геометрия), `pg_cron` (расписание).
- `etl_load_observations(pages)` — постранично `GET /v1/observations?project_id=flora-kazahstana&per_page=200&order_by=id&order=asc&id_above=<last>&locale=ru`, сохраняет **все** наблюдения (любой ранг определения), прогресс в `etl_state`.
- `etl_load_taxa(batches)` — `GET /v1/taxa/<ids>?locale=ru` для видов: русское/английское название, семейство, род, фото, Википедия.
- `etl_load_areas()` — области из geoBoundaries (KAZ ADM1) + схематичные полигоны природных зон, обрезанные по границе страны; привязка точек через `ST_Intersects`.
- `etl_refresh_stats()` — обновление материализованных представлений статистики.
- pg_cron: каждые 3 мин — следующая порция; каждые 10 мин — обновление статистики; по воскресеньям — полное обновление (сброс `last_id`).

### 5.2 Таблицы
- `observations`: id, taxon_id (вид, к которому сведено, может быть NULL), obs_taxon_id, obs_taxon_name, obs_taxon_rank, obs_common_name, observed_on, created_at, lat, lng, place_guess, quality_grade, user_login, user_icon, photo_url, uri, identifications_count, region, zone.
- `identifications`: id, observation_id, user_login, taxon_id, category, current, created_at.
- `taxa`: id, name, rank, common_name_ru, common_name_en, family, genus, photo_url, wikipedia_url, inat_url.
- `areas`: kind (region|zone), name, name_en, geom (PostGIS), geojson (упрощённый).

### 5.3 Материализованные представления (быстрые ответы < 1 с)
`mv_scope_species` (территория × вид × число наблюдений), `mv_scope_observers`, `mv_scope_identifiers`,
`mv_scope_stats` (счётчики по территории), `mv_scope_quality`, `mv_scope_month`, `mv_scope_year`,
`mv_scope_family`, `mv_map_cells` (сетка 0.05° с числом наблюдений для теплокарты).
Территория (`scope`) кодируется парой (`kind` ∈ all|region|zone, `name`).

### 5.4 RPC-функции для фронтенда (только чтение, роль `anon`)
`api_stats`, `api_species`, `api_observers`, `api_identifiers`, `api_observations` (с фильтрами и пагинацией),
`api_map_cells`, `api_map_points` (точки для вида/наблюдателя/территории), `api_quality`, `api_months`, `api_years`,
`api_families`, `api_taxon_months`, `api_taxon_areas`. RLS включён, запись только у ETL (security definer).

## 6. Фронтенд (Streamlit ≥ 1.40)
- `app.py` + `st.navigation`: **Обзор, Наблюдения, Виды, Эксперты, Наблюдатели, Статистика, Карта территорий, Вид**.
- Карты: `pydeck` — `HeatmapLayer`/`ColumnLayer` по `mv_map_cells` для всей страны, `ScatterplotLayer` с подсказками для выборок < 20 000 точек, `GeoJsonLayer` для границ; базовая карта Carto (без токена).
- Кеш `st.cache_data(ttl=600)`; при пустой базе — понятное сообщение о ходе загрузки (`etl_progress`).
- Стиль iNaturalist: шрифт без засечек, белые карточки с тенью, зелёный акцент, бейджи «N наблюдений» поверх фото, круглые аватары.
- Секреты: `SUPABASE_URL`, `SUPABASE_ANON_KEY` в `st.secrets`.
