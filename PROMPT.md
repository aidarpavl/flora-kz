# СУПЕР-ПРОМТ: «Флора Казахстана» — Streamlit + Supabase + iNaturalist

> Этот промт можно отдать любой LLM / разработчику, чтобы с нуля воспроизвести проект.

## Роль
Ты — senior full-stack разработчик и специалист по геоданным (Python, Streamlit, PostgreSQL/Supabase, GIS) с опытом в биоинформатике и ботанике. Пишешь чистый, документированный код, комментарии и интерфейс — на русском языке.

## Цель
Создать веб-приложение **«Флора Казахстана»** — аналог страницы проекта iNaturalist
https://www.inaturalist.org/projects/flora-kazahstana?tab=species, но с акцентом на Казахстан и с
**разделением на карте по трём уровням**:
1. **Весь Казахстан**;
2. **Области** (административное деление, ADM1);
3. **Природные зоны** (лесостепь, степь, полупустыня, пустыня, горные системы: Алтай, Саур-Тарбагатай, Джунгарский Алатау, Северный Тянь-Шань, Каратау).

## Стек
- **Источник данных:** iNaturalist API v1 (`https://api.inaturalist.org/v1`), проект `flora-kazahstana`.
- **База данных:** Supabase (PostgreSQL + PostgREST), проект `ucrhksetkgmhoxdwwhnh`.
- **ETL:** Python 3.11 (`requests`, `shapely`), запускается вручную и по расписанию в **GitHub Actions**.
- **Фронтенд:** Streamlit (≥1.36, `st.navigation`), карты — `pydeck` (входит в Streamlit), графики — `st.bar_chart`.
- **Хостинг:** GitHub → Streamlit Community Cloud (`app.py` как точка входа).
- **Секреты:** `st.secrets` / переменные окружения; `service_role`-ключ только в ETL/GitHub Secrets, во фронтенде — только `anon`-ключ.

## Модель данных (Supabase)
- `taxa` — виды: `id` (iNat taxon id), `name` (латынь), `rank`, `common_name_ru`, `common_name_en`, `family`, `genus`, `photo_url`, `wikipedia_url`, `inat_url`.
- `observations` — наблюдения: `id`, `taxon_id` (вид, к которому сведено наблюдение), `observed_on`, `lat`, `lng`, `quality_grade`, `user_login`, `photo_url`, `uri`, `region`, `zone`.
- `areas` — геометрии: `kind` ∈ {`region`,`zone`}, `name`, `name_en`, `geojson` (jsonb, упрощённый GeoJSON).
- Представления: `area_stats` (виды/наблюдения/наблюдатели по каждой области и зоне), `project_stats`, `family_stats`, `taxon_areas`.
- Функция `species_list(p_kind, p_name, p_q, p_limit, p_offset)` — список видов с числом наблюдений для выбранной территории, поиск по латинскому/русскому названию, пагинация.
- RLS включён, у роли `anon` — только `SELECT`.

## ETL (etl/load_inat.py)
1. Скачать наблюдения проекта постранично (`order_by=id&order=asc&id_above=…&per_page=200`), не чаще 1 запроса/сек, с повторами при ошибках, инкрементально (продолжать с максимального `id` в БД).
2. Оставлять только наблюдения до уровня вида и ниже; подвиды сводить к виду (`min_species_taxon_id`).
3. Определить для каждой точки **область** (point-in-polygon по границам ADM1 из geoBoundaries) и **природную зону** (по полигонам `data/kz_natural_zones.geojson`, горные системы имеют приоритет; зоны обрезаются по границе Казахстана).
4. Догрузить сведения о видах (`/v1/taxa/{ids}`, `locale=ru`): русское название, семейство, род, фото, Википедия.
5. Записать всё в Supabase через REST (`upsert`, пачками по 500).

## Интерфейс (стиль iNaturalist: белый фон, зелёный акцент `#74AC00`, карточки видов с фото)
- **Обзор:** счётчики (наблюдения, виды, наблюдатели), топ семейств, топ наблюдателей, мини-карта.
- **Виды:** переключатель территории (Весь Казахстан / Область / Природная зона) → выбор конкретной; поиск; сетка карточек (фото, русское и латинское название, число наблюдений, ссылка на iNat); пагинация; кнопка «Подробнее».
- **Карта:** режимы «Области» / «Природные зоны» / «Весь Казахстан»; хороплет по числу видов, подсказки при наведении; слой точек наблюдений; под картой — таблица территорий и топ видов выбранной территории.
- **Вид:** карточка вида, карта его находок, список областей и зон, где он встречается, последние наблюдения со ссылками.
- Кеширование запросов (`st.cache_data`, TTL 1 ч); понятные сообщения, если база пустая или не настроены секреты.
